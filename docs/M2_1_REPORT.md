## Schema verification and field semantics

The official App Server documentation was read, and the installed `codex-cli 0.166.0` generated both JSON Schema and TypeScript bindings without starting a provider session. The exact schema is included as a reviewable fixture in this change's file set, not as an assertion of live delivery. Its SHA-256 is `aba4f6c7e4a19b2b842c08ee793b57000c07dafd57b922ad0d8e7c76609108c2`. Version-pinned public source mapping was checked separately. See [the contract and source links](CONTEXT_TELEMETRY.md#verified-contract-and-research).

`total` is retained as cumulative reported usage; `last` is retained as latest reported usage. Both contain input, cached input, cache-write input, output, reasoning output, and reported aggregate counters. Cache and reasoning counters are not added again. Missing cache-write count defaults to zero according to JSON Schema. Missing or null `modelContextWindow` remains unknown. Required IDs identify thread and turn; this event supplies no authenticated session-root ID, timestamp, sequence, or event identity. [Every field and validation rule is documented](CONTEXT_TELEMETRY.md#field-meanings).

The source can provide synthetic aggregate counts. The parser therefore rejects totals below input plus output but does not require exact equality. It rejects nonfinite, unsafe, negative, fractional, malformed, null, or inconsistent counts and unsupported fields/shapes, including ambiguous duplicate JSON keys. It never deduces completion or compaction from a count change.

## Context calculation and status

There is no numeric active-context calculation for the supported event. Both cumulative/window and latest/window occupancy ratios are withheld. The adapter records unknown occupancy, and every imported Codex observation yields an unknown advisory. Source shape verification does not authenticate local input or prove that it reflects a current provider session.

The reusable advisory evaluator accepts only a fresh verified active-context measurement. It compares `100 * used >= configuredThreshold * window` with exact `BigInt` arithmetic and inclusive boundaries, returns the highest reached label, and has no external effects. No production adapter currently supplies an eligible measurement. This preserves the existing 60/75/90 default configuration without guessing utilization.

Commands implemented:

```text
contextbridge context status --project PATH [--session ID --thread ID]
contextbridge context ingest --project PATH --source codex-app-server
  --source-version 0.166.0 --session ID --observed-at UTC_ISO_TIMESTAMP
  --sequence POSITIVE_INTEGER --yes
```

Ingest accepts one bounded stdin notification. Status distinguishes supported capability from unavailable/stale observations and shows each stream independently. A local acquisition ID explicitly separates capture epochs. Sequence and original observation time must be provided by the caller; provenance marks both as unverified. Reports replace snapshots rather than incrementing totals. Replays preserve report age and cannot double-count usage. Declining counters are supported without assuming monotonicity. Five minutes is the exact stale boundary.

## Security, privacy, and recovery

Only numeric metadata and hashed identifiers persist in a separate store. No source, prompts, transcript, tool output, final response, credentials, or raw event file is retained. Existing memory/configuration/snapshot/handoff formats are unchanged. Every import requires explicit opt-in; status is read-only and creates no telemetry files. [Exact security and recovery guarantees](CONTEXT_TELEMETRY.md#storage-privacy-and-recovery) include 16 KiB input, five-second stdin deadline, 64 streams, 256 KiB published storage, strict validation, single-writer exclusion, symlink/hardlink rejection, and fixed exclusive staging before synced atomic replacement.

The checksum is an integrity check, not authentication. Deterministic identifier hashing is not encryption. Caller-supplied ordering/time cannot prove real provider history. Filesystem checks do not defend against hostile concurrent replacement. Sync/rename provides ordinary process-interruption recovery, not a complete power-loss transaction. Crash leftovers require operator inspection and manual removal after confirming no writer is active; no takeover, destructive reset, eviction, or automatic promotion is performed.

## Actual integration support and remaining work

Implemented: verified event parser, explicit local import, persistent observation snapshots, source/provenance/freshness status, and a generic advisory evaluator.

Unimplemented: automatic event capture from App Server, interactive Codex CLI, or existing VS Code sessions; active occupancy verification; live notifications; lifecycle-driven freshness invalidation; compaction control; interruption; session switching; automatic rollover.

M1.2 `SessionStart`/`Stop` hooks do not expose the required usage fields. The reviewed public IDE documentation did not establish a telemetry subscription for existing extension conversations. Neither the completed owner-reported memory-capture smoke tests nor the common App Server protocol demonstrates ContextBridge telemetry capture in VS Code. Private extension interception was not attempted.

Next work requires a deliberately managed, opt-in App Server client with source-order routing, bounded content-free transport handling, lifecycle metadata, authenticated smoke tests, and an independently justified occupancy metric. Continuous CLI and VS Code monitoring must be validated against supported public integration contracts separately. Broader version support, cross-platform execution evidence, authenticated source provenance, retention management, and lifecycle-aware invalidation remain explicit follow-ups.
